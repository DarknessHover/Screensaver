## 1. 产品定位

一款运行在 Android 上的屏保应用：用户上传本地图片作为素材，按"每天循环"的时间窗口自动切换显示。同时支持两种呈现形态，可在设置中切换。

## 3. 功能需求（FR）

- **FR1 素材管理**：素材绑定在规则上，**每规则 1 张图**（无独立图片库）。在规则编辑时经 SAF 选图并持久化 URI；未选图时禁止保存。规格不符时**自适应 centerCrop 裁切**兜底展示，而非报错拒绝。**v3：素材按壁纸域区分——每域的规则绑定该域所用的图（屏保规则绑锁屏图、桌面规则绑桌面图），互不混用。**
- **FR2 规则创建**：在 0–24h 时间轴预览时间段；起止时间支持**点击卡片弹出 TimePicker 精确编辑**（精确到分）与时间轴区间联动；跨午夜由用户在编辑器里拆成两条规则表达（时间轴为线性、不支持跨午夜）；每天重复固定。**时间段冲突约束：新规则起止区间不得与任一其它规则区间重叠（类火车票禁选），编辑时不与自己冲突。v3：新建规则须先指定壁纸域（屏保/锁屏 或 桌面），两域规则各自独立时间线；冲突检查仅在**同一域内**进行，跨域区间不互斥。v6：编辑器不再有"规则名称"输入——规则唯一标识由起止时间承担。v9（2026-09-01）：新建规则的默认壁纸域 = 进入编辑器前首页停留的域（经导航参数 `domain` 传递），编辑已有规则时以规则自身的域为准。**
- **FR3 调度引擎**：在时间点切换"当前生效素材"；跨午夜由用户拆两条规则表达（线性时间轴不支持跨午夜），算法层只需 `start ≤ now < end` 单一判断，无需 wrap-around 分支。**v3：引擎按壁纸域分域解析——屏保域的规则只用于解析锁屏壁纸、桌面域的规则只用于解析桌面壁纸；两个域各自独立判断与触发，互不影响。**
- **FR4 渲染-Daydream**：设备空闲/充电时全屏显示当前素材，动图需有动画。**状态：未实现（待迭代，见 PLAN）。**
- **FR5 渲染-壁纸**：**v3：将"当前生效规则"按其隶属的壁纸域，仅应用到对应壁纸——屏保域 → 锁屏壁纸(FLAG_LOCK)；桌面域 → 桌面壁纸(FLAG_SYSTEM)。不再"同一张图同时设为锁屏 + 桌面"，两个域独立生效、可同时共存。**
- **FR6 启动恢复**：开机后重新排程并恢复当前生效素材。
- **FR7 设置与引导**：模式切换、权限按需申请、跳转 Daydream 设置页、电池优化引导。**状态（2026-09-01）：无独立设置页**——应用只有首页与规则编辑器两个界面，模式切换（Daydream）与 Daydream 设置页跳转随 FR4 一并待迭代；现有的引导只有首页精确闹钟 Banner 一处。
- **FR8 后台静默存活（v4）**：在常规后台（系统回收/划卡）下依赖闹钟自动换壁纸；对"释放内存/强制停止"——提供**忽略电池优化白名单引导 + 国产 ROM 自启/后台保护白名单引导 + UI 预警提示**（路线A），尽可能提高定时不被打断的概率。说明能力上限：用户主动"强停"后无法自动恢复（Android 安全机制），需 UI 明确告知。
  - **实现边界（2026-09-09 更新）**：已实现 = ①精确闹钟未授权 Banner；②**电池优化白名单引导**——权限 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` + 首页"后台保活未授权"提示卡（状态驱动：未授权显示 / 授权消失 / 撤销复现），跳转 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 失败兜底应用详情页。**未实现（待迭代）** = 厂商私有设置页跳转表（档二）、现象自检"上次成功切换时间戳"（v2）。
  - 🔴 **2026-09-07 根因确认**：国产 ROM 上闹钟到点与亮屏补偿两条后台路径失效，**根因是 OEM 耗电/后台策略在闹钟唤醒后限制或冻结进程**。实测证据链：任务管理锁定后台无效 → 精确闹钟权限已授予仍失效 → 多机型复现 → **解除系统耗电管理后切换准确**。修复路线分析见 `ANALYSIS_后台保活授权引导可行性_20260907.md`；修复档①（引导卡）已于 2026-09-09 落地并通过静态验收，**待真机对照验收**（加白前后对照 / 拔线纪律）。

## 11. 后台存活与文档建设决策（2026-08-26）
### 11.1 问题①——"释放内存"强停后的定时失效【已拍板：路线A】
- **现状**：本应用纯闹钟驱动、无常驻服务；进程被系统回收/划卡后闹钟仍在、到点可触发（✅）；但"释放内存/强制停止"会**取消全部闹钟并进入停止态**，`BOOT_COMPLETED`/闹钟/广播均不投递，定时失效且无法自愈，必须用户重开一次（❌）。
- **能力上限**：Android 安全模型禁止第三方应用阻止 force-stop；系统级/预装应用才豁免。故目标是**最大化存活概率**而非绝对免疫。
- **结论（路线A，已拍板）**：忽略电池优化白名单引导 + 国产 ROM 自启/后台保护白名单引导 + UI 预警提示；前台服务（路线B）列为后续增强。
