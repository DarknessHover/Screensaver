## 1. 分层

```
UI (Jetpack Compose)
   ↓ StateFlow
ViewModel
   ↓
Domain（ScheduleEngine 纯函数，无 Android 依赖）
   ↓
Data（Room）
   +
Framework（AlarmManager / BroadcastReceiver / WallpaperManager）
```

- 包结构：`com.screensaver.ui`（UI + ViewModel + theme/components/util）、`com.screensaver.domain`（仅 `scheduler/ScheduleEngine`）、`com.screensaver.data`（Room 与仓储）、`com.screensaver.scheduler`（闹钟与系统交互，属 Framework 层）、`com.screensaver.di`（手动 DI）。

## 3. 数据模型（Room）

**版本策略**：`AppDatabase.version = 1`，`exportSchema = false`，容器侧 `fallbackToDestructiveMigration()`。

> 本应用未上架、日常迭代即卸载重装，规则数据重建成本极低。schema 变更时直接 `version + 1` 让 Room 破坏性重建空库，**不编写逐代 Migration**。故"库版本"不再随字段演进而递增，下述字段演进只是历史记录。

单表 `rules`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `start_minute` | INTEGER | 当天第几分钟，0..1440 |
| `end_minute` | INTEGER | 永远 > `start_minute`，≤ 1440 |
| `image_uri` | TEXT | SAF 持久化 `content://` URI；**字段可空**，但编辑器强制选图后才允许保存（未选图拒绝保存） |
| `wallpaper_domain` | TEXT | `LOCK`（屏保/锁屏）/ `SYSTEM`（桌面，默认） |
| `created_at` | INTEGER | 创建时间戳 |

- 关键约束（「剪开拉直」）：单条记录不跨午夜，`end > start ≤ 1440`；跨午夜由用户在编辑器拆两条；引擎只需 `start ≤ now < end`，无 wrap-around 分支。
- 规则唯一标识：起止时间（`label` 字段已删）；`observeAll()` 按 `start_minute ASC` 排序，首页另按所选域过滤后再升序。
- 字段演进记录（**历史，非库版本**）：
  - v4 移除图片库与多对多关联表 `RuleImageCrossRef`（及 `ImageDao`）
  - v5 移除 `enabled` 列（所有规则默认生效）
  - v6 移除 `repeat_daily` 列（MVP 仅每天循环，字段恒为 true 属冗余）
  - v7 新增 `wallpaper_domain` 列（默认 SYSTEM），按壁纸域独立时间线与冲突检查
  - v8 删除 `label` 列（规则唯一标识由起止时间承担）
- **素材不入库**：图片以 SAF 持久化 URI 直接存于规则 `image_uri`，无独立图片库/图片表。

## 4. 时间窗口算法（`domain/scheduler/ScheduleEngine`，纯函数）

- `toMinuteOfDay(h, m) = h*60 + m`（工具函数在 `ui/util/TimeFormat.kt` 的 `nowMinuteOfDay()`，基于 `Calendar` 以兼容 API 24/25）。
- **`resolve(now, rules, domain): ScheduleRuleEntity?`**：先按 `wallpaperDomain` 过滤，再取满足 `start ≤ now < end` 中 `startMinute` 最小者；无命中返回 `null`（→ 上层不干预，O4）。
  - 重叠不再用 `priority` 裁决：编辑器已禁止建重叠区间（REQ O3），故取最早开始段即可。
- **`boundaryMinutes(rules): Set<Int>`**：全部规则 `start`/`end` 的并集去重，作为闹钟边界（两域共用 [0,1440) 分钟空间，唤醒后按域各自解析）。
- **`getAllIntervals(rules, domain, excludeRuleId = null): List<Pair<Int, Int>>`**：供编辑器做冲突检查，排除自身（编辑时不与自己冲突）。

## 6. 触发路径与唯一入口

**唯一写入入口**：`AppContainer.applyCurrentNow()` → `applyDomain(rules, now, domain)`（日志 TAG `WallpaperSwitch`）。按域解析 → 命中且有 `imageUri` → `WallpaperApplier.apply(uri, domain)`；无命中则该域不干预（O4）。**勿再造第二份实现。**

触发点（五处，全部汇入同一入口）：

```
① MainActivity.onCreate（前台，100% 生效）
② 规则保存 / 删除后（RuleEditorViewModel.save / HomeViewModel.deleteRule）
③ BootCompletedReceiver（BOOT_COMPLETED + MY_PACKAGE_REPLACED）
④ WallpaperSwitchReceiver（闹钟到点，goAsync + IO 协程；触发后自愈式 scheduleAll()）
⑤ ScreenOnReceiver（亮屏补偿，仅 LOCK 域；动态注册于 ScreensaverApplication，生命周期=进程）
```

- `AlarmScheduler.scheduleAll()`：先取消请求码 0..1440 的全部闹钟，再对每个边界分钟用 `setExactAndAllowWhileIdle`（API 31+ 未授权降级 `setAndAllowWhileIdle`；API 23–30 精确；API <23 用 `setExact`）。**无规则时不注册任何闹钟**（O4）。
- 保存链路：`RuleEditorViewModel.save()` → `findConflict()` 冲突校验 → 未选图则拒绝（Snackbar）→ 写入 → `scheduleAll()` + `applyCurrentNow()`。
- 🔴 **已知问题（2026-09-07 根因确认）**：国产 ROM 上 ④⑤ 两条后台路径未能生效，只有打开 APP 才换壁纸。**根因 = OEM 耗电/后台策略在闹钟唤醒后限制或冻结进程**（用户实测：解除系统耗电管理后壁纸准确切换；多机型复现、任务锁定无效、精确闹钟权限已授予）。对应修复 = FR8 的耗电白名单引导，见 `ANALYSIS_后台保活授权引导可行性_20260907.md`。

## 7. UI 与导航

| 路由 | 说明 |
|---|---|
| `home` | 首页 |
| `editor/{ruleId}?domain={domain}` | 规则编辑器；`ruleId = -1` 表示新建，`domain` 默认 `SYSTEM`，解析失败回退 `SYSTEM` |

- 视觉规范：`DESIGN_UI视觉规范_20260901.md`（v7，按当前代码重写；旧 v5/v6 已因多次迭代内容混乱被项目负责人删除）。**改 UI 必须回写该规范。**

  - **空态条款（2026-09-01 修订）**：空态只给文字指引，**主操作由常驻 FAB 承担**，空态内不再内嵌"新建"按钮（此两者曾构成同屏双入口）。
  - FAB 新建携带 `domain=${selectedTab.name}`，编辑器据此**预选壁纸域**（2026-09-01 修复：此前新建恒为 SYSTEM，与来源 Tab 脱钩）。

- 时间精度 1 分钟；首页在前台时每 60s `recomputeCurrent()`，`ON_RESUME` 亦重算（暖启动不走 `onCreate`）。
