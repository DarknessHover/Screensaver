# Screensaver 文档索引

本目录分别维护产品意图、当前实现、运行证据和历史资料。阅读项目时从本页进入，不再从文件名日期推断哪个版本有效，也不把“代码现状”与“产品应当怎样”混为同一种事实。

## 如何判定事实

不同类型的事实各有归属，不使用一条总优先级相互覆盖：

1. **产品意图：** 项目负责人当前决定、需求文档与 UI 设计规范；
2. **当前实现：** 可达代码、Gradle/Manifest/Room 配置，以及架构和应用流程 HTML；
3. **观测证据：** 可复现测试、构建输出、日志与注明环境的真机结果；
4. **历史事实：** 原始需求、退休的架构/计划快照和 Git 历史；
5. `learning_for_human` 中的教学资料不作为产品或实现约束。

产品意图与当前实现不一致时，必须记录为“设计—实现偏差”，不得静默让其中一方覆盖另一方。

## 当前状态

- 工程：Android / Kotlin / Jetpack Compose / Room / AlarmManager。
- 构建基线：Gradle 8.9，JDK 21，AGP 8.5.2，Kotlin 1.9.24，`minSdk 24`、`targetSdk 34`、`compileSdk 34`。
- 自动验证：`compileDebugKotlin`、19 个 JVM 单元测试、`lintDebug`、`assembleDebug` 已通过；Lint 为 0 error。
- 真机证据：整理前版本已由项目负责人确认在 3 台真机正常运行。本轮审查调整了调度、URI 授权和失败恢复链路，针对性真机回归清单见应用流程文档。

## 维护规则

- 产品目标、范围或用户可见行为变化时更新需求文档；颜色、Token、组件或交互决策变化时更新 UI 视觉规范。
- 结构、依赖、数据或系统契约变化时更新架构文档；运行路径、条件或出口变化时更新应用流程文档。
- 旧架构和开发计划只追加必要的状态说明，不再把新事实回写到退休快照。
- 不在核心文档保留版本流水账、聊天过程、已删除文件清单或失效链接；这些信息由 Git 历史承担。
- 未实现内容必须标为限制或缺口，不画成现有能力。
- 构建或真机结论必须附带可复现命令或明确的观察来源。
- HTML 是节点和关系的唯一事实源；CSS/JavaScript 只提供视觉布局、连接线和直接关系高亮。
