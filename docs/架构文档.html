快速认识这个项目

Screensaver 是一个只有 app 的单 Gradle 模块 Android 应用：用户为锁屏或桌面建立每天重复的图片规则；Room 保存规则；AlarmManager 只安排下一次规则开始；到点后重新解析两个壁纸域并通过 WallpaperManager 设置壁纸。应用没有轮询、前台服务或云端依赖。

两个独立壁纸域

LOCK 使用 FLAG_LOCK，SYSTEM 使用 FLAG_SYSTEM。规则和冲突检查按域隔离。

每天重复的线性时间

规则采用左闭右开区间 [start, end)，单条不跨午夜；跨午夜需要手工拆成两条。

单闹钟链式调度

始终只保留最近的下一次开始闹钟，触发后再排下一次。空档结束不切换，继续保持已有壁纸。

本地 URI，不复制图片

Storage Access Framework 返回 content:// URI；应用保存持久读取授权和 URI 字符串。

手动依赖注入

AppContainer 在 Application 中构造 Room、仓储、调度器和壁纸应用器，没有 Hilt。

事实来源

当前源码、Manifest、Gradle、Room schema 与测试优先于历史文档。本页描述当前实现，不描述理想架构。

系统与哪些外部能力交互？

这张图划定应用边界。Android 系统和文档提供器都在应用进程之外；Room 数据库属于应用私有存储；真实壁纸是 WallpaperManager 的外部副作用。

源码逻辑组件如何依赖？

本节的“组件”是类、包和职责边界，不是独立 Gradle module。依赖大体遵循 UI → ViewModel → 容器/仓储/领域 → Android 适配器。ScheduleEngine 是唯一不依赖 Android 的核心规则组件；AppContainer 是跨路径共享处理器。

图片 URI 和规则怎样存活？

图片本身不进入数据库。数据库只保存 URI；能否长期读取取决于 ContentResolver 中的持久授权。替换或删除规则时以“数据库是否仍有引用”作为释放条件。

Room 数据契约

数据库没有跨行区间约束，最终合法性依赖 ViewModel 保存前校验。第三方代码若绕过 ViewModel 直接写 DAO，必须自行维护同样约束。

区间语义

start <= now < end。结束点不再命中当前规则。

跨午夜

单条规则不支持 wrap-around；22:00–02:00 必须拆成 22:00–24:00 和 00:00–02:00。

同域冲突

UI/VM 禁止重叠，但数据库没有 UNIQUE/EXCLUDE/CHECK 能阻止并发或旁路写入。

旁路重叠兜底

若数据库已出现同域重叠，resolve 选择 startMinute 最小者；相同 startMinute 的平局取决于输入顺序，而 DAO 的全量查询没有排序保证，因此不应把它当作 priority 或完全确定的裁决。

无图重叠行

resolve 不过滤空 URI。若旁路数据产生重叠且最先命中的规则无图，应用链会选择它后跳过设置，不会继续寻找另一条有图规则。

迁移策略

版本为 1，启用 fallbackToDestructiveMigration()；schema 变化允许清空规则。

权限、线程与恢复契约

能力用途获得/复查位置失败或撤销后的行为
SET_WALLPAPER设置两个壁纸域Manifest 普通权限系统调用异常返回 false 并写日志
RECEIVE_BOOT_COMPLETED重启后恢复排程Manifest + BootCompletedReceiver未收到广播时等待用户打开应用
SCHEDULE_EXACT_ALARMAPI 31+ 精确切换首页提示；onResume 与授权广播复查未授权降级 setAndAllowWhileIdle；可能延迟
REQUEST_IGNORE_BATTERY_OPTIMIZATIONS降低部分 ROM 后台冻结概率首页提示；onResume 查询 PowerManager不保证厂商执行，也不能解除 force-stop
SAF 持久读授权长期读取用户图片选图回调取得并验证失败则拒绝选择；最后引用删除后释放
主线程

Compose、导航回调和 ViewModel 事件在主线程；挂起后回到 viewModelScope 主调度器。

IO 工作

Room、闹钟重排、图片读取和壁纸设置在 Dispatchers.IO；当前规则纯计算可在 Default。

Receiver 生命周期

异步 Receiver 调用 goAsync()，并在 finally 中 finish；仍受系统广播时间预算约束。

锁屏失败恢复

FLAG_LOCK 失败后以 elapsedRealtime 进入 30 分钟进程内退避；成功后清零，不永久熔断。

本地时间

规则分钟和 RTC_WAKEUP 都使用设备当前本地日历时间。当前没有监听手动改时、时区变化或日期变化；这些变化后要到下一次已有入口重排才会校正。

并发所有权

AppContainer 没有全局互斥或任务队列。Activity、ViewModel 与多个 Receiver 的协程可能重叠；数据库重叠校验和 WallpaperManager 调用都不是跨入口串行事务。

Receiver 与 action 的实际归属

Receiver注册方式接收 action核心动作
BootCompletedReceiverManifest 静态、exportedBOOT_COMPLETED、MY_PACKAGE_REPLACED、精确闹钟授权状态改变前两者先重排再应用双域；授权广播复查成功后只重排

当前限制与明确缺口

限制当前真实行为开发者注意事项
用户强制停止系统阻止闹钟和广播，应用无法自行恢复用户再次打开 MainActivity 后才会重排
厂商后台策略即使有闹钟和白名单，也可能冻结或延迟进程不要把电池白名单描述成绝对保证
厂商锁屏实现FLAG_LOCK 可能被主题/锁屏组件拒绝当前使用 30 分钟退避并记录日志
并发写入重叠保存前会重读检查，但没有数据库事务约束新增写入口时必须复用校验或补数据库级保护
未保存 URI 授权选图后取消、校验失败，或同一编辑会话再次选图时，先前取得的持久授权可能没有业务引用但仍保留当前没有启动对账或编辑器销毁清理；未来应按数据库引用释放
系统时间或时区变化没有注册 TIME_SET / TIMEZONE_CHANGED 等恢复入口，既有 RTC 闹钟不会由应用主动重算变更时间相关代码时补 Receiver，并验证 DST/手动改时
亮屏补偿生命周期ScreenOnReceiver 只在应用进程存活时存在，不能用亮屏启动已死亡进程它是 LOCK 补偿，不是可靠调度入口
多入口并发保存、启动和 Receiver 任务没有全局串行化；后完成的系统调用可能覆盖先完成者若新增高并发入口，应评估互斥、幂等与版本检查
数据库升级schema 变化允许破坏性重建若要面向真实用户发布，必须先改迁移策略
系统集成测试AlarmManager、Receiver、WallpaperManager 没有自动仪器测试相关改动必须真机回归

术语速查

术语在本项目中的通俗含义
壁纸域 / domain壁纸目标的逻辑分区：LOCK 是锁屏，SYSTEM 是桌面；两条时间线互不冲突。
resolve给定“当前分钟 + 全部规则 + 一个域”，选出至多一条当前命中规则；无命中返回 null。
startMinutes从合法且有图的规则中提取去重后的开始分钟集合，供调度器选择下一次唤醒。
PendingIntent交给 Android 系统保管的、未来可触发本应用 Receiver 的令牌；应用进程无需常驻。
SAF 持久 URI 授权用户选图后授予应用跨重启读取该 content:// 地址的能力；不是图片副本。
goAsync()让 BroadcastReceiver 在 onReceive 返回后短暂继续异步工作；最终必须调用 finish()，且仍有系统时间预算。
elapsedRealtime设备开机后的单调时钟，用来计算 30 分钟 LOCK 退避，不受用户修改墙上时间影响；进程重启会丢失本项目的内存退避状态。
RTC_WAKEUP / Doze按真实日历时间唤醒设备的闹钟类型；Doze 是系统省电状态，精确能力不足时系统可延迟非精确闹钟。
fallbackToDestructiveMigrationRoom 找不到迁移脚本时删除旧库并重建；本项目当前会因此丢失全部规则。
